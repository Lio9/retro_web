0. 目标、范围与硬约束

先把「做什么 / 不做什么」钉死，避免在 RA 合规和模拟器细节上走弯路。

产品目标（按优先级）

  1. 浏览器内稳定运行 NDS 游戏：双屏、键盘映射、可选触摸、基本 60fps（桌面 Chromium 优先）。
  2. 本地存档可靠持久化：游戏内保存写入 IndexedDB，可导出/导入 .sav。
  3. 云端存档同步：Java 后端提供上传/下载/列表 API，跨设备恢复。
  4. 接入 RetroAchievements：游戏中实时解锁并上报，遵守官方反作弊规则。

明确不做（红线）

  • 禁止伪造 ROM 哈希、双 ROM 切换「补进度」、内存改写刷成就。
  • 禁止内置作弊码 / 金手指 / 任意内存编辑器并用于 Hardcore。
  • 禁止分发任何商业 ROM、BIOS、固件；一律用户本地自备。
  • 禁止把「汉化 ROM 当英文原版上报」当作产品能力宣传或实现。
合规底线（必须写进 README 与 UI） RA 只认数据库内登记的 ROM 哈希。汉化/修改版若无官方新哈希，成就系统会正确地拒绝解锁—— 这是预期行为，不是 bug。产品应引导用户走「翻译补丁哈希申请」官方流程，而不是绕过校验。

成功标准（可验收）

阶段 验收标准
P0 模拟器 加载合法自备 NDS ROM，双屏显示，键盘可操作，主菜单/进游戏无崩溃
P1 本地存档 游戏内存档后刷新页面仍在；可导出 .sav 并在另一浏览器导入恢复
P2 后端账号 注册/登录、JWT 会话、存档上传下载 API 可用 Postman 验证
P3 云同步 两台设备同一账号，版本冲突可检测并提示，不静默覆盖
P4 成就 英文原版 ROM 可解锁成就并出现在 RA 网站；Hardcore 规则生效

1. 总体架构图

三条主线：浏览器内模拟器运行时、Java 云存档服务、RA 成就集成层。 成就评估尽量在客户端（rcheevos WASM）完成，后端只做账号、存档与可信上报通道。

数据流（关键路径）

  1. 启动游戏：用户本地选择 .nds（可选 BIOS/FW）→ WASM 加载 ROM → 双屏渲染循环启动。
  2. 输入：键盘/触摸映射为 NDS 按键位 → 写入模拟器输入寄存器状态。
  3. 存档：游戏内保存 → 核心导出 SRAM/flash 为 .sav 字节 → 写 IndexedDB（防抖，如 2s）→ 可选推送云端。
  4. 云同步：客户端带 revision 上传 → 后端比较版本 → 成功则 revision+1，冲突则 409 并返回双方元数据。
  5. 成就：每帧/定时读游戏内存 → rcheevos rc_client 评估 → 解锁事件 → 存本地 + 调 RA API 上报（经后端代理更稳妥）。
职责切分建议 你的 Java 优势应该花在：账号、存档版本、配额、限流、RA token 保管、审计日志。 模拟器帧循环、成就表达式求值都留在浏览器 WASM，不要用 Java 再包一层模拟器。

2. 分阶段实现路线图

五个阶段串行推进，每个阶段都有独立可演示的产出。估算按兼职/熟悉 Java 的开发者：每阶段约 1–2 周有效工作量。

P0
约 1 周

跑通模拟器核心

目标：浏览器里能玩起来。不做账号、不做云、不做成就。

  • 选定并构建 melonDS WASM（或先用现成可运行的 web 移植验证）。
  • 页面加载 ROM / 可选 BIOS 与 firmware。
  • 双屏 Canvas 渲染 + 键盘映射 + 基础音效开关。
  • 固定时间步（60fps）主循环，暂停/重置可用。
  • 产出：index.html + 核心封装 emu/melon-bridge.js。
P1
约 3–5 天

本地存档（IndexedDB + .sav）

目标：关掉浏览器进度不丢，能备份恢复。

  • 捕获电池存档字节（SRAM/Flash），写入 IndexedDB。
  • 自动保存防抖 + 手动「立即保存」。
  • 导出 .sav / 导入 .sav；显示最近保存时间与大小。
  • 用「游戏标识」做键：优先 ROM 哈希，其次文件名+大小（需提示不够精确）。
  • 产出：storage/save-store.js、UI 存档面板。
P2
约 1–2 周

Java 后端与账号

目标：Spring Boot 服务可部署，JWT 登录，存档 API 契约定稿。

  • Spring Boot 3.x + PostgreSQL：用户、游戏档案、存档元数据表。
  • 登录/注册（先邮箱密码即可）；JWT（或 Session Cookie）。
  • 存档上传/下载/列表 API；blob 存 MinIO 或先存 PG bytea（规模小可接受）。
  • 版本字段 revision + 乐观锁，冲突返回 409。
  • 产出：OpenAPI 文档、Docker Compose（api + postgres + minio）。
P3
约 1 周

云存档同步

目标：跨设备恢复可靠，冲突不丢档。

  • 登录后启动对比本地/云端 revision 与时间戳。
  • 策略：新设备下载 → 玩一会 → 上传；冲突弹窗「保留本地 / 用云端 / 两者都导出」。
  • 上传失败重试、网络中断队列；限速与单档大小上限。
  • 审计：谁在何时覆盖了哪一版。
  • 产出：同步状态条、冲突对话框、同步测试用例。
P4
约 1–2 周

RetroAchievements 接入

目标：英文原版可实时解锁成就；Hardcore 规则生效；汉化路径合规。

  • 集成 rcheevos（WASM 或经现有封装），rc_client 加载游戏与成就定义。
  • 实现只读内存 peek 回调；禁止任何写内存接口暴露给成就层。
  • ROM 哈希识别 → 匹配 RA game id → 拉取成就列表 → 帧末评估 → 解锁 toast。
  • 登录 RA（建议经你的后端代理，API Key/Web API 不暴露在前端）。
  • Hardcore：禁用即时存档/快进/作弊；Softcore 允许存档。
  • 产出：成就面板、解锁通知、合规说明页、汉化 ROM 引导流程。

阶段依赖关系

顺序建议 P0 → P1 可完全离线交付；P2 可在 P1 同步开发 API（接口先定契约）；P3 依赖 P2； P4 只读依赖 P0 的内存访问接口，但不依赖云存档。因此 P4 可与 P3 并行，前提是 ROM 哈希识别已经可用。

关于 melonDS WASM 获取路径

路径 A：社区现成 Web 移植（先跑通）

  • 寻找 DS Anywhere / melonDS-wasm 等开源演示，研究其胶水层。
  • 直接复用其 .js/.wasm 与 API 形状，替换 UI。
  • 优点：几天能玩起来；缺点：API 可能不完整，存档钩子要自己补。

路径 B：自己 Emscripten 编译 melonDS（可控）

  • 克隆 melonDS，用 Emscripten 工具链编译核心。
  • 显式导出：加载 ROM、步进帧、读帧缓冲、读写 SRAM、按键。
  • 优点：接口干净，便于 rcheevos peek；缺点：编译环境折腾。
现实建议 P0 用路径 A 验证产品方向；一旦要认真做 RA 和云存档，再切到路径 B 拥有稳定 C API。 不要同时维护两套核心。

4. 关键代码骨架

以下骨架按「能对接」为目标，不是可直接复制粘贴的完整实现。 接口名以你最终选用的 WASM 导出为准，但职责边界建议保持不变。

4.1 加载 melonDS WASM 并渲染双屏

// emu/melon-bridge.js —— 双屏渲染与主循环骨架
export class MelonBridge {
  constructor({ topCanvas, bottomCanvas }) {
    this.topCanvas = topCanvas;
    this.bottomCanvas = bottomCanvas;
    this.topCtx = topCanvas.getContext("2d");
    this.bottomCtx = bottomCanvas.getContext("2d");
    this.running = false;
    this._raf = 0;
    this._saveDebounceMs = 2000;
    this._onSave = null;
    this._onFrame = null;
  }

  // 1) 初始化 WASM 模块（替换为你构建产物的加载函数）
  async init(wasmUrl) {
    // 假设 Emscripten 导出 createModule
    this.mod = await createModule({
      locateFile: (p) => new URL(p, wasmUrl).href,
      canvas: this.topCanvas, // 部分移植用单 canvas 叠双屏
    });
    this.HEAPU8 = () => this.mod.HEAPU8;
  }

  // 2) 加载 ROM（用户文件 -> 字节 -> 核心）
  async loadRom(file) {
    const buf = new Uint8Array(await file.arrayBuffer());
    // 示例：导出 cwrap 接口；名字以实际导出为准
    const ptr = this.mod._malloc(buf.length);
    this.mod.HEAPU8.set(buf, ptr);
    this.mod._nds_load_rom(ptr, buf.length);
    this.mod._free(ptr);
    this.romId = await this.computeRomId(buf); // 用于存档键与 RA 哈希
  }

  // 3) 双屏绘制：NDS 原生 256x192 x2
  blitFrame() {
    // 从核心帧缓冲读 RGB565/RGBA，分别画到上下屏
    const w = 256, h = 192;
    const topPtr = this.mod._nds_framebuffer_top();
    const botPtr = this.mod._nds_framebuffer_bottom();
    const top = new ImageData(
      new Uint8ClampedArray(this.mod.HEAPU8.buffer, topPtr, w * h * 4), w, h
    );
    const bot = new ImageData(
      new Uint8ClampedArray(this.mod.HEAPU8.buffer, botPtr, w * h * 4), w, h
    );
    this.topCtx.putImageData(top, 0, 0);
    this.bottomCtx.putImageData(bot, 0, 0);
    this._onFrame && this._onFrame();
  }

  // 4) 固定 60fps 步进；用 rAF 对齐显示器刷新
  start() {
    if (this.running) return;
    this.running = true;
    let acc = 0, last = performance.now();
    const step = () => {
      if (!this.running) return;
      const now = performance.now();
      acc += now - last;
      last = now;
      // 1000/60 ≈ 16.67ms 一帧
      while (acc >= 16.67) {
        this.mod._nds_run_frame();
        acc -= 16.67;
      }
      this.blitFrame();
      this._raf = requestAnimationFrame(step);
    };
    this._raf = requestAnimationFrame(step);
  }

  stop() {
    this.running = false;
    cancelAnimationFrame(this._raf);
  }

  // 5) 输入：把浏览器键位映射为 NDS 按键位图
  bindKeyboard(map = defaultKeyMap) {
    const held = new Set();
    window.addEventListener("keydown", (e) => {
      if (held.has(e.code)) return;
      held.add(e.code);
      const bit = map[e.code];
      if (bit != null) {
        e.preventDefault();
        this.mod._nds_set_input(bit, 1);
      }
    });
    window.addEventListener("keyup", (e) => {
      held.delete(e.code);
      const bit = map[e.code];
      if (bit != null) this.mod._nds_set_input(bit, 0);
    });
  }

  // 触摸：底屏坐标转内部分辨率
  bindTouch(bottomCanvas) {
    const toLocal = (ev) => {
      const r = bottomCanvas.getBoundingClientRect();
      const x = ((ev.clientX - r.left) / r.width) * 256;
      const y = ((ev.clientY - r.top) / r.height) * 192;
      return { x: Math.floor(x), y: Math.floor(y) };
    };
    bottomCanvas.addEventListener("pointerdown", (ev) => {
      const { x, y } = toLocal(ev);
      this.mod._nds_touch(x, y, 1);
      bottomCanvas.setPointerCapture(ev.pointerId);
    });
    bottomCanvas.addEventListener("pointermove", (ev) => {
      if (!ev.buttons) return;
      const { x, y } = toLocal(ev);
      this.mod._nds_touch(x, y, 1);
    });
    bottomCanvas.addEventListener("pointerup", () => {
      this.mod._nds_touch(0, 0, 0);
    });
  }

  async computeRomId(bytes) {
    // 优先用稳定哈希（MD5/CRC32）。RA 自身用特定算法，后面单独做 RA 识别。
    const digest = await crypto.subtle.digest("SHA-256", bytes);
    return [...new Uint8Array(digest)].map((b) => b.toString(16).padStart(2, "0")).join("");
  }

  onFrame(fn) { this._onFrame = fn; }
}

const defaultKeyMap = {
  ArrowUp: 0, ArrowDown: 1, ArrowLeft: 2, ArrowRight: 3,
  KeyX: 4, KeyZ: 5, KeyA: 6, KeyS: 7,
  Enter: 8, ShiftLeft: 9, // Start / Select
  KeyQ: 10, KeyW: 11,     // L / R
};

4.2 捕获 .sav 存档数据

NDS「电池存档」通常是 SRAM / Flash / EEPROM 映射在核心内部。 正确做法是通过 WASM 导出的 只读导出接口 拿到连续字节，不要手算内部结构体偏移。 

// storage/save-store.js —— 本地 .sav 持久化骨架
export class SaveStore {
  constructor(dbName = "nds-web-emu") {
    this.dbName = dbName;
    this.dbPromise = this.open();
  }

  open() {
    return new Promise((resolve, reject) => {
      const req = indexedDB.open(this.dbName, 1);
      req.onupgradeneeded = () => {
        const db = req.result;
        if (!db.objectStoreNames.contains("saves")) {
          const os = db.createObjectStore("saves", { keyPath: "id" });
          os.createIndex("gameId", "gameId");
          os.createIndex("updatedAt", "updatedAt");
        }
        if (!db.objectStoreNames.contains("meta")) {
          db.createObjectStore("meta", { keyPath: "gameId" });
        }
      };
      req.onsuccess = () => resolve(req.result);
      req.onerror = () => reject(req.error);
    });
  }

  // 从模拟器核心导出当前电池存档
  extractSav(mod) {
    // 约定导出：_nds_sav_size() / _nds_export_sav(ptr, size)
    const size = mod._nds_sav_size();
    const ptr = mod._malloc(size);
    mod._nds_export_sav(ptr, size);
    const bytes = new Uint8Array(mod.HEAPU8.buffer, ptr, size).slice();
    mod._free(ptr);
    return bytes; // 通常可直接作为 .sav 文件下载
  }

  async putLocal({ gameId, romName, bytes, revision = 0 }) {
    const db = await this.dbPromise;
    const record = {
      id: gameId + ":local",
      gameId,
      romName,
      bytes,
      revision,
      updatedAt: Date.now(),
    };
    return new Promise((resolve, reject) => {
      const tx = db.transaction("saves", "readwrite");
      tx.objectStore("saves").put(record);
      tx.oncomplete = () => resolve(record);
      tx.onerror = () => reject(tx.error);
    });
  }

  async getLocal(gameId) {
    const db = await this.dbPromise;
    return new Promise((resolve, reject) => {
      const tx = db.transaction("saves", "readonly");
      const req = tx.objectStore("saves").get(gameId + ":local");
      req.onsuccess = () => resolve(req.result || null);
      req.onerror = () => reject(req.error);
    });
  }

  exportFile(bytes, filename = "game.sav") {
    const blob = new Blob([bytes], { type: "application/octet-stream" });
    const a = document.createElement("a");
    a.href = URL.createObjectURL(blob);
    a.download = filename;
    a.click();
    URL.revokeObjectURL(a.href);
  }

  async importFile(file, gameId, mod) {
    const bytes = new Uint8Array(await file.arrayBuffer());
    // 回写核心，使当前会话立即使用该存档
    const ptr = mod._malloc(bytes.length);
    mod.HEAPU8.set(bytes, ptr);
    mod._nds_import_sav(ptr, bytes.length);
    mod._free(ptr);
    await this.putLocal({ gameId, romName: file.name, bytes });
  }
}

// 与桥接层串起来：游戏内保存后防抖写入
export function attachAutoSave(bridge, store, gameId) {
  let timer = 0;
  bridge.onFrame(() => {
    // 也可以改为定时 5s 轮询导出，或核心提供 dirty 标志
    clearTimeout(timer);
    timer = setTimeout(async () => {
      const bytes = bridge.extractSav(bridge.mod);
      if (!bytes || bytes.length === 0) return;
      await store.putLocal({ gameId, romName: bridge.romName, bytes });
    }, bridge._saveDebounceMs);
  });
}
存档实现要点 不同游戏存档类型不同（512B / 8KB / 64KB / 256KB / 512KB flash）。导出接口必须返回真实使用的长度， 导入时按长度校验。另：即时存档（Save State）与电池存档（.sav）是两套东西——RA Hardcore 禁用前者，不禁用后者的游戏内保存。

4.3 Java 后端存档 API（含版本冲突）

// SaveSyncController.java —— Spring Boot 3 骨架
@RestController
@RequestMapping("/api/saves")
@RequiredArgsConstructor
public class SaveSyncController {

    private final SaveSyncService saveSyncService;

    /** 列表：仅返回元数据，避免大文件打爆带宽 */
    @GetMapping
    public List<SaveMetaDto> list(Authentication auth) {
        return saveSyncService.listSaves(userId(auth));
    }

    /** 下载：带 ETag，便于客户端条件请求 */
    @GetMapping("/{gameId}/blob")
    public ResponseEntity<Resource> download(
            @PathVariable String gameId,
            @RequestHeader(value = "If-None-Match", required = false) String inm,
            Authentication auth) {
        SaveBlob blob = saveSyncService.openBlob(userId(auth), gameId);
        String etag = "\"" + blob.revision() + "\"";
        if (etag.equals(inm)) {
            return ResponseEntity.status(HttpStatus.NOT_MODIFIED).eTag(etag).build();
        }
        return ResponseEntity.ok()
                .eTag(etag)
                .header("X-Save-Revision", String.valueOf(blob.revision()))
                .contentType(MediaType.APPLICATION_OCTET_STREAM)
                .body(blob.resource());
    }

    /**
     * 上传：乐观锁。
     * clientRevision = 客户端认为的当前版本。
     * 若服务端更新，则 409，由客户端决定合并策略。
     */
    @PutMapping("/{gameId}/blob")
    public ResponseEntity<SaveMetaDto> upload(
            @PathVariable String gameId,
            @RequestHeader("If-Match") long clientRevision,
            @RequestBody byte[] payload,
            Authentication auth) {
        try {
            SaveMetaDto meta = saveSyncService.save(
                    userId(auth), gameId, clientRevision, payload);
            return ResponseEntity.ok(meta);
        } catch (RevisionConflictException ex) {
            return ResponseEntity.status(HttpStatus.CONFLICT)
                    .header("X-Server-Revision", String.valueOf(ex.serverRevision()))
                    .body(null); // 也可返回 {serverRevision, serverUpdatedAt} JSON
        }
    }

    private String userId(Authentication auth) {
        return (String) auth.getPrincipal();
    }
}
// SaveSyncService.java —— 冲突与存储骨架
@Service
@RequiredArgsConstructor
public class SaveSyncService {

    private final SaveMetaRepository metaRepo;
    private final SaveBlobStore blobStore; // MinIO / S3 / 或 PG

    @Transactional
    public SaveMetaDto save(String userId, String gameId, long clientRevision, byte[] payload) {
        if (payload.length > 8 * 1024 * 1024) {
            throw new IllegalArgumentException("save too large");
        }
        SaveMeta meta = metaRepo.findByUserIdAndGameId(userId, gameId)
                .orElseGet(() -> SaveMeta.builder()
                        .userId(userId).gameId(gameId).revision(0L)
                        .build());

        // 关键：乐观锁检查，防止两端互相覆盖
        if (meta.getRevision() != clientRevision) {
            throw new RevisionConflictException(meta.getRevision());
        }

        long next = meta.getRevision() + 1;
        String key = String.format("saves/%s/%s/%d.sav", userId, gameId, next);
        blobStore.put(key, payload);

        meta.setRevision(next);
        meta.setByteSize(payload.length);
        meta.setSha256(sha256(payload));
        meta.setUpdatedAt(Instant.now());
        meta.setStorageKey(key);
        metaRepo.save(meta);
        return SaveMetaDto.from(meta);
    }

    public SaveBlob openBlob(String userId, String gameId) {
        SaveMeta meta = metaRepo.findByUserIdAndGameId(userId, gameId)
                .orElseThrow(NotFoundException::new);
        return new SaveBlob(meta.getRevision(), blobStore.open(meta.getStorageKey()));
    }

    public List<SaveMetaDto> listSaves(String userId) {
        return metaRepo.findByUserId(userId).stream().map(SaveMetaDto::from).toList();
    }

    private static String sha256(byte[] data) {
        try {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            return HexFormat.of().formatHex(md.digest(data));
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);
        }
    }
}

// achievements/ra-client.js —— 成就评估骨架（WASM rcheevos）
export class RaIntegration {
  constructor({ mod, memoryReader, apiBase }) {
    this.mod = mod;                 // rcheevos wasm 模块
    this.memoryReader = memoryReader; // (addr, size) => Uint8Array，只读
    this.apiBase = apiBase;         // 建议指向你的 Java 后端代理
    this.client = null;
    this.mode = "softcore";         // hardcore | softcore | off
  }

  async login(username, password) {
    // 不要把 RA 密码直连浏览器到 RA；走你的后端，由后端调 RA Web API
    const res = await fetch(this.apiBase + "/ra/login", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ username, password }),
      credentials: "include",
    });
    if (!res.ok) throw new Error("RA login failed");
    this.session = await res.json(); // 含 token 由后端保管/下发短期凭证
  }

  async identifyAndLoadGame(romBytes) {
    // 1) 用 RA 认可的哈希算法计算 ROM 哈希（务必与 RA 文档一致）
    const hash = await computeRaRomHash(romBytes);
    // 2) 查询该游戏是否有成就
    const info = await fetch(this.apiBase + "/ra/game?hash=" + hash).then(r => r.json());
    if (!info || !info.gameId) {
      this.game = null;
      return { supported: false, hash, reason: "hash-not-in-ra-db" };
    }
    this.game = info;
    // 3) 初始化 rc_client 并加载成就定义（可通过后端缓存 rapi 数据）
    this.client = this.mod.rc_client_new(this.memoryReader, this.session);
    this.mod.rc_client_load_game(this.client, info.gameId, null, 0);
    return { supported: true, game: info, hash };
  }

  // 每帧末调用：读内存 -> 求值 -> 回调解锁
  pumpFrame() {
    if (!this.client || this.mode === "off") return;
    const events = this.mod.rc_client_do_frame(this.client);
    for (const ev of events || []) {
      if (ev.type === "unlock") {
        this.onUnlock && this.onUnlock(ev.achievement);
        this.reportUnlock(ev.achievement.id);
      } else if (ev.type === "game-complete") {
        this.onGameComplete && this.onGameComplete();
      }
    }
  }

  async reportUnlock(achievementId) {
    // 本地先记一笔，再异步上报，失败重试
    await this.persistLocalUnlock(achievementId);
    await fetch(this.apiBase + "/ra/unlock", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        achievementId,
        hardcore: this.mode === "hardcore",
        when: new Date().toISOString(),
      }),
      credentials: "include",
    });
  }

  setMode(mode) {
    // hardcore 强制关闭即时存档/快进/作弊入口
    this.mode = mode;
  }

  onUnlock = null;
  onGameComplete = null;
}

// 只读内存适配器 —— 绝不要暴露写接口
function makeMemoryReader(mod) {
  return (address, size) => {
    // 从 melonDS 导出只读 peek；address 为 NDS 体系结构地址
    const ptr = mod._nds_peek(address, size);
    return new Uint8Array(mod.HEAPU8.buffer, ptr, size).slice();
  };
}
反作弊实现约束 成就层只允许 peek/read。任何 poke/write 不得对成就逻辑开放。 Hardcore 模式必须同时：禁用 Save State、禁用快进、禁用作弊、使用快速重置（Quick Reset）策略（以 RA 文档为准）。 上报走服务端可避免浏览器直接持有 RA 密码，也便于做审计。

5. 中文 ROM 与 RA 合规处理方案

这是你特别强调的部分：产品能力应当是「识别 + 引导 + 官方补哈希」，绝不是「骗过哈希」。

5.1 现实规则（务必写进产品文案）

  • RA 成就绑定的是已登记 ROM 哈希，不是游戏剧情进度本身。
  • 中文汉化 ROM 哈希与英文原版不同，通常默认不在 RA 数据库。
  • 官方认可的汉化途径：把汉化补丁作为 translation patch 申请新增哈希，由成就开发者/审核添加。
  • 禁止：拿英文 ROM 哈希「贴牌」中文 ROM、双开 ROM 同步进度、改内存解锁。

7. 风险与注意事项

这些坑大多会直接造成「丢档」或「成就失效」，建议在设计阶段就留好对策。

7.1 技术风险

风险 影响 缓解措施
IndexedDB 被浏览器驱逐 本地存档丢失 及时云同步；提示用户导出 .sav；用 navigator.storage.persist() 申请持久化存储
WASM 性能不足 掉帧、音画不同步 关闭调试层；降低滤镜；优先 Chromium；必要时降低音频采样率；避免每帧 JS 大拷贝
帧缓冲拷贝开销 CPU 打满 用 WebGL 纹理直传；零拷贝视图；双缓冲
存档时序竞态 坏档/半份写入 核心「导出为原子快照」；IndexedDB 事务提交后再标成功；云端写临时 key 再切换
多端同时写 进度回退 严格 revision 乐观锁；冲突 UI 必选；禁止自动 last-write-wins 覆盖
ROM 哈希算法不一致 RA 无法识别 严格按 RA 文档实现哈希；用已知英文原版样本做测试向量

7.2 RA 规则与产品风险

  • Hardcore 限制：禁 Save State、禁作弊、禁快进（以官方最新规则为准）。你的 UI 在 Hardcore 下必须隐藏/禁用这些入口，而不是只在上报时忽略。
  • 反作弊审查：出现「内存编辑解锁成就」会连带账号风险。代码评审时把 poke/write 列为禁用符号。
  • 汉化预期管理：社区常见投诉是「为什么中文版不解锁」。文案、论坛置顶、成就页状态徽章要一致。
  • API 限流与密钥泄露：RA 调用走后端代理；密钥只在服务端；对 unlock 做幂等与速率限制。
  • 法律与分发：绝不上传用户 ROM 到服务器做「云端模拟」（除非有明确授权）；演示站只用无版权争议材料。

7.3 浏览器兼容

  • 首要目标：桌面 Chrome / Edge；次目标：Firefox、Safari。
  • 移动端：触摸映射可玩，但 NDS 双屏小屏体验差；建议横屏布局 + 虚拟按键。
  • iOS Safari 对 WASM/音频有限制，需单独验收。
最容易被低估的一条 「本地存档」和「云存档」如果用两套不一致的 revision 逻辑，会互相覆盖。 请把 单一 Save Model（本地记录也带 revision）从 P1 就定下来，P3 只是增加远端指针，而不是重写模型。

8. 省力替代方案（当现有栈难扛时）

若某一块超出你的前端精力或工期，用这些替换策略，不要硬啃。

模拟器 WASM 难编译

  • 直接采用已验证的 Web 移植产物（合法开源协议），只做 UI 与存档桥。
  • 或先做「桌面 melonDS + Web 仅做启动器/云存档」过渡（体验差一档但可上线）。

前端写不动复杂 UI

  • UI 做薄：加载、双屏、存档三按钮、成就列表即可。
  • 使用成熟组件库（如 Pico.css / 简单组件），把时间留给 WASM 桥。

云同步想更快上线

  • 第一版只做「上传 / 下载 / 强制选择」，不做自动合并。
  • 存储可先用 PostgreSQL bytea，量上来再迁 MinIO/R2。

RA 集成想降风险

  • 先做「哈希识别 + 成就列表展示」，解锁上报随后补。
  • 上报可先支持 Softcore，Hardcore 作为第二里程碑。

完全托管/半托管混合（最省人力）

方案：前端静态 + 你的 Java 只做「存档与账号」
RA：第一期仅识别与展示（纯前端只读）
    第二期再加后端代理上报

这样即使 rcheevos WASM 集成延期，产品仍可上线获得用户反馈。
不推荐的捷径 用现成「云游戏模拟器」SaaS 直接套壳、或用 PHP/Node 写一份与 Java 并行的后端。 后者会让你的维护成本翻倍，而且与「用 Java 做后端」的初衷冲突。
